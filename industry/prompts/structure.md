四、资料范围 scope：只根据这篇资料自身判断，不能从候选报道反推。
- single：核心报道只有一个具体发生，或围绕该发生的一项分析、复现、回应。同一份通告里的多个受影响产品与版本区间属于 single。没有具体发生的单一观点或技术讲解可以是 single，但 fact 为 null；不能用“讨论同一个议题”把多个发生合成 single。
- composite：正文实质性报道多个可以各自成条的发生：一次月度补丁汇总里互不相关的若干漏洞、一次安全周报里的多条事件、多位研究者各自披露的不同漏洞，都是 composite。共同厂商、同一发布日期、同一份公告合集都不能把它们变成一次发生。仅把其他漏洞或厂商用作背景、比较或例证，正文仍集中于一个发生或一项方法，则不是 composite。
- unknown：材料不足以辨认范围。不要仅凭标题词、篇幅或是否能抽到 fact 判断。

五、事实 fact：抽取本条资料当前报道的那次发生，供同事实归组使用：title（≤30 字），subject（做出动作的主体），action（本次动作），object（动作的具体对象），occurredAt（原文明示的本次动作发生日期 YYYY-MM-DD，未知为 null）。厂商/CERT/公告库发布的通告以发布机构为 subject，即使消息由员工账号或研究团队宣布；个人的技术分析或复现本身以作者为主体，不因其任职单位就声称机构发布。composite 必须为 null；没有可确认发生的观点稿也可为 null。
本行业的当前动作要如实区分：**披露 / 确认在野利用 / 被实际利用攻击 / 公开 PoC / 发布补丁 / 发布缓解措施 / 更正或撤回通告 / 复盘**。这些是不同的动作，不能互相替代，也不能由“高危”“严重”“紧急”推断出“已在野利用”。
先分清当前动作与背景：
- 标题里的 CVE 编号通常就是本次动作的对象；一条资料涉及多个编号时，以正文主报的那个为准。
- 新写的技术分析、复现记录、检测规则涉及既有漏洞时，抽取这次分析/复现及其明确新增内容，不能因正文回顾了漏洞而仍写“披露了该漏洞”。例：“上月的洞，今天我们给出可利用链” → 动作是给出利用链。
- 主帖仅转述或引介引用帖、自己没有另一项动作时，可以抽取引用中被转述的同一次发生；不要把一次转发本身虚构成厂商的新通告。
- 发布时间、抓取时间、被引用帖的时间不能补作当前动作的日期。“今天”可结合本条原文发布时间解析；只有背景日期或没有明确日期时保持 null。
- 长期维护的漏洞档案页、CVE 编号索引、参数与版本表、安全公告汇总页，仅罗列既有条目、没有原文明示的新动作时，scope 为 unknown、fact 为 null；不能把“页面收录了”改写成“机构新披露了”。
fact 非 null 时还包含 evidence 和 conditions：evidence 只复制支持核心事实的一句原文（≤600 字符，找不到为 null）；conditions 是最多 4 条决定结论适用范围的原文短句，每条只有 {"quote":"原文的一句连续短句（≤400字符）"}。本步骤不翻译、不概括条件，只摘录。
evidence 必须支持上面选定的当前动作。主帖有新动作时从主帖摘取，不拿引用中的旧通告句子证明本次复现；只有主帖纯转述引用时才用引用帖的核心证据。
通读全文（包括文末的影响版本、修复版本和缓解说明）后，条件优先级为：1. 利用条件（是否需要认证、是否需要本地权限、是否需要非默认配置、是否影响默认配置）；2. 受影响的产品与版本区间；3. 已发布的补丁版本、缓解措施与修复截止期限。不要用“危害极大”“影响广泛”这类评价占用条件名额。没有明确条件才给 []，不要把“厂商称已修复”写成“已验证修复”。
每个 quote 只承载一句原文；不同位置的条件分别成项，不能串成一个段落。例：原文有 “Requires authentication.” 和 “Fixed in 2.4.51.”，应输出 [{"quote":"Requires authentication."},{"quote":"Fixed in 2.4.51."}]，不能写成 “Requires authentication... Fixed in 2.4.51.”。保持原文语言和字符；超过长度就选较短的完整句子。不要翻译、改写、省略中间文字或自行加入 ... / …；拼接的引文会被丢弃。quote 必须是收到的原文正文/帖子里能连续查到的文字，不来自标题、来源标签或中文译文。

输出前核对当前动作（优先于标题和宣传措辞）：标题里的“紧急”“立即修复”“已遭利用”不能覆盖正文明确的先后关系。正文若说目前只有通告、尚无利用证据，本次 action 就只能是披露；只有正文明确写出已在野利用，才写确认在野利用。evidence 摘取当前动作的句子，不能摘背景句来证明新状态。没有明示本次动作发生在哪一天，occurredAt 必须为 null，不从文章发布时间或 CVE 发布日期补齐。

材料只是一份文档、页面、仓库或工具的发布与更新，正文未披露任何具体漏洞（无编号、无受影响组件、无利用状态与修复信息）时，category 给 null——**不要为了有值而套一个类别**。
